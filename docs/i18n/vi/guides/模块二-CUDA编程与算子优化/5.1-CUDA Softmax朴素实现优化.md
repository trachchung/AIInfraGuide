## 1. Softmax cơ bản và vấn đề số

### 1.1 Softmax là gì

Giả sử bạn có một đống điểm số và muốn biết "mức độ quan trọng của mỗi điểm so với tổng thể" — điểm cao chiếm phần lớn, điểm thấp chiếm phần nhỏ, và tất cả cộng lại đúng bằng 1. Softmax làm đúng việc đó: nó "nén" một tập số thực bất kỳ thành một phân phối xác suất.

Định nghĩa toán: với vector đầu vào $\mathbf{x} = (x_0, x_1, \ldots, x_{N-1})$, Softmax cho:

$$
\text{Softmax}(x_i) = \frac{e^{x_i}}{\sum_{j=0}^{N-1} e^{x_j}}
$$

Trong Self-Attention của Transformer, Softmax chạy trên từng hàng của ma trận $QK^T$, biến điểm attention thô thành trọng số đã chuẩn hóa. Độ dài đầu vào thường là độ dài chuỗi $N$ (2048, 4096, thậm chí 128K), nên Softmax hiệu quả ảnh hưởng trực tiếp tới hiệu năng tổng thể của mô hình.

### 1.2 Vấn đề tràn số

Công thức Softmax dùng phép mũ $e^{x_i}$, rất dễ tràn trong biểu diễn số thực:

- **FP32**: giá trị lớn nhất khoảng $3.4 \times 10^{38}$, tương ứng $e^{88.7}$. Khi $x_i > 88.7$, $e^{x_i}$ thành `+inf`
- **FP16**: max khoảng $6.55 \times 10^4$, tương ứng $e^{11.09}$. Khi $x_i > 11$ đã tràn
- **Underflow cũng nguy hiểm**: khi $x_i$ rất nhỏ (ví dụ $-100$), $e^{x_i} \approx 0$, mẫu số có thể dưới tràn về 0 và sinh `NaN`

Trong Attention thực tế, giá trị $QK^T$ dễ vượt 88 (nhất là khi $d_k$ lớn và chưa scale). Bản naive chắc chắn sập.

### 1.3 Cách xử lý: trừ max

Về toán có thể chứng minh: trừ cùng một hằng số $c$ khỏi mọi phần tử không đổi kết quả Softmax:

$$
\frac{e^{x_i - c}}{\sum_{j} e^{x_j - c}} = \frac{e^{x_i} \cdot e^{-c}}{\sum_{j} e^{x_j} \cdot e^{-c}} = \frac{e^{x_i}}{\sum_{j} e^{x_j}}
$$

Chọn $c = \max(\mathbf{x})$. Mọi số mũ đều có đối số $\leq 0$, kết quả nằm trong $(0, 1]$, hết rủi ro tràn trên. Đó là lõi của **Safe Softmax** (Softmax ổn định số).

### 1.4 Luồng tính toán và điểm nghẽn

Safe Softmax tự nhiên tách thành **ba lần quét** (Three-Pass):

| Lần | Thao tác | Biểu thức |
|-----|----------|-----------|
| Lần 1 | Tìm max hàng | $m = \max_j(x_j)$ |
| Lần 2 | Cộng mũ | $d = \sum_j e^{x_j - m}$ |
| Lần 3 | Chuẩn hóa | $y_i = e^{x_i - m} / d$ |

Mỗi lần đọc cả hàng. Với vector dài $N$, tổng cộng $3N$ lần đọc global memory. Softmax có cường độ số học thấp (khoảng 1–2 phép toán thực mỗi lần đọc), thuộc dạng **memory-bound** điển hình. Mục tiêu tối ưu là **giảm số lần truy cập bộ nhớ** và **tăng tỷ lệ dùng băng thông**.

### 1.5 Môi trường đo

Mọi code trong bài viết bằng CUDA 12.x, đo trên A100 80GB SXM4:

| Chỉ số | Giá trị |
|--------|---------|
| Băng thông bộ nhớ lý thuyết | 2 TB/s |
| Số SM | 108 |
| Shared Memory mỗi SM | 164 KB |

Cấu hình đo: hình dạng ma trận $(M, N) = (4096, 4096)$ — 4096 hàng, mỗi hàng 4096 phần tử (mô phỏng Attention điển hình).

## 2. Phiên bản V0: triển khai naive (một thread một hàng)

### 2.1 Ý tưởng thuật toán

Chiến lược song song đơn giản nhất: mỗi thread xử lý độc lập một hàng của ma trận đầu vào, tuần tự làm max, exp-sum, normalize. Các hàng hoàn toàn độc lập, song song tự nhiên.

### 2.2 Kernel

```cuda
// V0: bản naive, một thread xử lý một hàng
__global__ void softmax_v0(float* input, float* output, int M, int N) {
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row >= M) return;

    float* x = input  + row * N;
    float* y = output + row * N;

    // Pass 1: tìm max
    float max_val = -INFINITY;
    for (int i = 0; i < N; i++) {
        max_val = fmaxf(max_val, x[i]);
    }

    // Pass 2: cộng mũ
    float sum = 0.0f;
    for (int i = 0; i < N; i++) {
        sum += expf(x[i] - max_val);
    }

    // Pass 3: chuẩn hóa
    float inv_sum = 1.0f / sum;
    for (int i = 0; i < N; i++) {
        y[i] = expf(x[i] - max_val) * inv_sum;
    }
}
```

### 2.3 Phân tích hiệu năng

⚠️ **Lưu ý**: V0 đúng nhưng hiệu năng rất kém, vì ba lý do:

1. **Độ song song thấp**: mỗi hàng chỉ 1 thread; $N=4096$ phần tử bị xử lý tuần tự. Hàng nghìn CUDA Core hầu như ngồi không
2. **Truy cập không coalesced**: 32 thread trong một warp xử lý 32 hàng khác nhau; địa chỉ trong vòng lặp trong lệch nhau $N \times 4$ byte (một hàng), gây uncoalesced nặng
3. **Tính thừa**: `expf(x[i] - max_val)` bị tính hai lần ở Pass 2 và Pass 3

**V0 đo thực tế: ~5% băng thông (~102 GB/s)** — chạy được nhưng không dùng được.

## 3. Phiên bản V1: Safe Softmax quét ba lần

### 3.1 Hướng cải tiến

Vấn đề lõi của V0 là thiếu song song — $N$ phần tử của một hàng chỉ do 1 thread xử lý. Cách làm: để **nhiều thread trong một Block cùng xử lý một hàng**. Mỗi thread lo một đoạn; Shared Memory dùng cho reduce song song để ra max và sum.

Tức là tách Softmax thành hai Reduce (max-reduce + sum-reduce) cộng một phép element-wise (normalize). Mỗi Reduce dùng kỹ thuật đã học ở bài tối ưu Reduce.

### 3.2 Kernel

```cuda
// V1: một Block xử lý một hàng, reduce song song trong Block
__global__ void softmax_v1(float* input, float* output, int M, int N) {
    extern __shared__ float smem[];  // dùng cho reduce

    int row = blockIdx.x;
    int tid = threadIdx.x;

    float* x = input  + row * N;
    float* y = output + row * N;

    // Pass 1: tìm max song song
    float max_val = -INFINITY;
    for (int i = tid; i < N; i += blockDim.x) {
        max_val = fmaxf(max_val, x[i]);
    }
    smem[tid] = max_val;
    __syncthreads();

    // Reduce Shared Memory để lấy max toàn cục
    for (int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            smem[tid] = fmaxf(smem[tid], smem[tid + s]);
        }
        __syncthreads();
    }
    max_val = smem[0];
    __syncthreads();

    // Pass 2: cộng mũ song song
    float sum = 0.0f;
    for (int i = tid; i < N; i += blockDim.x) {
        sum += expf(x[i] - max_val);
    }
    smem[tid] = sum;
    __syncthreads();

    // Reduce Shared Memory để lấy tổng
    for (int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            smem[tid] += smem[tid + s];
        }
        __syncthreads();
    }
    sum = smem[0];
    __syncthreads();

    // Pass 3: chuẩn hóa và ghi ra
    float inv_sum = 1.0f / sum;
    for (int i = tid; i < N; i += blockDim.x) {
        y[i] = expf(x[i] - max_val) * inv_sum;
    }
}
```

Cách gọi:

```cuda
int block_size = 256;
int smem_size = block_size * sizeof(float);
softmax_v1<<<M, block_size, smem_size>>>(d_input, d_output, M, N);
```

### 3.3 Phân tích hiệu năng

So với V0:
- **Độ song song tăng mạnh**: 256 thread cùng xử lý một hàng; mỗi thread chỉ lo $N/256 = 16$ phần tử
- **Truy cập coalesced**: các thread kề nhau trong Block đọc địa chỉ kề trong hàng (stride=1), coalesced đẹp

Vẫn còn:
- Reduce Shared Memory cần nhiều vòng `__syncthreads()`
- Ba lần quét nghĩa là input bị đọc 3 lần

**V1 đo thực tế: ~35% băng thông (~714 GB/s)**, khoảng 7× V0.

## 4. Phiên bản V2: tối ưu reduce bằng warp shuffle

### 4.1 Hướng cải tiến

Reduce của V1 phụ thuộc hoàn toàn Shared Memory, có hai vấn đề: dữ liệu đi vòng register → SMEM → register; mỗi vòng reduce cần `__syncthreads()`, và khi số thread còn ít thì chi phí sync chiếm tỷ lệ cao.

Từ kinh nghiệm tối ưu Reduce, Warp Shuffle (`__shfl_down_sync`) trao đổi dữ liệu trực tiếp giữa register: latency thấp hơn, không Bank Conflict, sync nội tại trong warp. Ta đổi reduce thành cấu trúc hai tầng "Shuffle trong Warp + Shared Memory giữa các Warp": mỗi Warp shuffle ra kết quả cục bộ, ghi vào mảng SMEM 32 phần tử, rồi Warp đầu làm reduce cuối.

### 4.2 Kernel

```cuda
// Reduce trong Warp: Max
__device__ float warpReduceMax(float val) {
    for (int offset = 16; offset > 0; offset >>= 1) {
        val = fmaxf(val, __shfl_down_sync(0xffffffff, val, offset));
    }
    return val;
}

// Reduce trong Warp: Sum
__device__ float warpReduceSum(float val) {
    for (int offset = 16; offset > 0; offset >>= 1) {
        val += __shfl_down_sync(0xffffffff, val, offset);
    }
    return val;
}

// Reduce hai tầng: Max trong Block
__device__ float blockReduceMaxShuffle(float val) {
    __shared__ float warp_max[32];

    int lane = threadIdx.x % 32;
    int wid  = threadIdx.x / 32;

    val = warpReduceMax(val);

    if (lane == 0) warp_max[wid] = val;
    __syncthreads();

    int num_warps = blockDim.x / 32;
    val = (lane < num_warps) ? warp_max[lane] : -INFINITY;
    if (wid == 0) val = warpReduceMax(val);

    // Broadcast kết quả cho mọi thread
    __shared__ float block_result;
    if (threadIdx.x == 0) block_result = val;
    __syncthreads();
    return block_result;
}

// Reduce hai tầng: Sum trong Block
__device__ float blockReduceSumShuffle(float val) {
    __shared__ float warp_sum[32];

    int lane = threadIdx.x % 32;
    int wid  = threadIdx.x / 32;

    val = warpReduceSum(val);

    if (lane == 0) warp_sum[wid] = val;
    __syncthreads();

    int num_warps = blockDim.x / 32;
    val = (lane < num_warps) ? warp_sum[lane] : 0.0f;
    if (wid == 0) val = warpReduceSum(val);

    __shared__ float block_result;
    if (threadIdx.x == 0) block_result = val;
    __syncthreads();
    return block_result;
}

// V2: reduce hai tầng bằng Warp Shuffle
__global__ void softmax_v2(float* input, float* output, int M, int N) {
    int row = blockIdx.x;
    int tid = threadIdx.x;

    float* x = input  + row * N;
    float* y = output + row * N;

    // Pass 1: tìm max hàng
    float local_max = -INFINITY;
    for (int i = tid; i < N; i += blockDim.x) {
        local_max = fmaxf(local_max, x[i]);
    }
    float max_val = blockReduceMaxShuffle(local_max);

    // Pass 2: cộng mũ
    float local_sum = 0.0f;
    for (int i = tid; i < N; i += blockDim.x) {
        local_sum += expf(x[i] - max_val);
    }
    float sum = blockReduceSumShuffle(local_sum);

    // Pass 3: chuẩn hóa
    float inv_sum = 1.0f / sum;
    for (int i = tid; i < N; i += blockDim.x) {
        y[i] = expf(x[i] - max_val) * inv_sum;
    }
}
```

### 4.3 Vì sao Warp Shuffle nhanh hơn

| Tiêu chí | Reduce Shared Memory | Reduce Warp Shuffle |
|----------|----------------------|---------------------|
| Đường dữ liệu | Register → SMEM → register | Register → register |
| Bank Conflict | Có thể có | Không |
| Chi phí sync | Mỗi vòng cần `__syncthreads()` | Sync nội tại trong warp |
| Latency | ~20–30 cycles | ~5 cycles |

💡 **Gợi ý**: Latency của Warp Shuffle khoảng 1/4 đến 1/6 Shared Memory (~5 cycles so với ~20–30 cycles), và không cần `__syncthreads()`. Ở giai đoạn reduce khi số thread đã ít, khoảng cách latency và việc bỏ sync ảnh hưởng rõ tới hiệu năng tổng.

**V2 đo thực tế: ~52% băng thông (~1060 GB/s)**, khoảng 1.5× V1.

## 5. Phiên bản V3: tải vector hóa float4

### 5.1 Hướng cải tiến

Nút thắt của V2 đã chuyển sang giai đoạn tải global memory. Mỗi vòng lặp, mỗi thread chỉ tải 1 `float` (4 byte); chi phí phát lệnh cao so với lượng dữ liệu. Dùng `float4` tải vector hóa, mỗi lệnh mang 16 byte (4 float), giúp:

- Giảm tổng số lệnh load (giảm 4 lần số vòng lặp)
- Tăng hiệu quả giao dịch bộ nhớ
- Tăng song song mức lệnh (ILP)

### 5.2 Kernel

```cuda
// V3: tải vector hóa float4
__global__ void softmax_v3(float* input, float* output, int M, int N) {
    int row = blockIdx.x;
    int tid = threadIdx.x;

    float* x = input  + row * N;
    float* y = output + row * N;

    // Con trỏ vector hóa
    float4* x4 = reinterpret_cast<float4*>(x);
    float4* y4 = reinterpret_cast<float4*>(y);
    int N4 = N / 4;  // số phần tử float4

    // Pass 1: tìm max vector hóa
    float local_max = -INFINITY;
    for (int i = tid; i < N4; i += blockDim.x) {
        float4 data = x4[i];
        local_max = fmaxf(local_max, fmaxf(fmaxf(data.x, data.y),
                                            fmaxf(data.z, data.w)));
    }
    // Xử lý phần đuôi (khi N không chia hết cho 4)
    for (int i = N4 * 4 + tid; i < N; i += blockDim.x) {
        local_max = fmaxf(local_max, x[i]);
    }
    float max_val = blockReduceMaxShuffle(local_max);

    // Pass 2: cộng mũ vector hóa
    float local_sum = 0.0f;
    for (int i = tid; i < N4; i += blockDim.x) {
        float4 data = x4[i];
        local_sum += expf(data.x - max_val) + expf(data.y - max_val)
                   + expf(data.z - max_val) + expf(data.w - max_val);
    }
    for (int i = N4 * 4 + tid; i < N; i += blockDim.x) {
        local_sum += expf(x[i] - max_val);
    }
    float sum = blockReduceSumShuffle(local_sum);

    // Pass 3: chuẩn hóa vector hóa
    float inv_sum = 1.0f / sum;
    for (int i = tid; i < N4; i += blockDim.x) {
        float4 data = x4[i];
        float4 result;
        result.x = expf(data.x - max_val) * inv_sum;
        result.y = expf(data.y - max_val) * inv_sum;
        result.z = expf(data.z - max_val) * inv_sum;
        result.w = expf(data.w - max_val) * inv_sum;
        y4[i] = result;
    }
    for (int i = N4 * 4 + tid; i < N; i += blockDim.x) {
        y[i] = expf(x[i] - max_val) * inv_sum;
    }
}
```

### 5.3 Cải thiện hiệu năng

Số vòng lặp mỗi thread giảm từ $N/\text{blockDim}$ xuống $N/(4 \times \text{blockDim})$ — giảm 4 lần chi phí vòng lặp và phát lệnh. Đồng thời `float4` che latency bộ nhớ tốt hơn.

⚠️ **Lưu ý**: `float4` đòi hỏi mảng đầu vào căn 16 byte. Trong thực tế thường cấp phát bằng `cudaMalloc` (căn 256 byte), và đảm bảo $N$ chia hết cho 4 (không thì dùng vòng đuôi).

**V3 đo thực tế: ~65% băng thông (~1325 GB/s)**, khoảng 1.25× V2.

## 6. Phiên bản V4: kernel hợp nhất hai lần quét

### 6.1 Phần thừa của ba lần quét

Nhìn lại V1–V3: ba lần quét đọc input 3 lần. Với ma trận $(4096, 4096)$, tổng đọc là $3 \times 4096 \times 4096 \times 4 = 192$ MB. Nếu gộp Pass 2 (exp-sum) và Pass 3 (normalize) thành một lần, còn 2 lần đọc (128 MB) — giảm 1/3 lưu lượng, tốc độ lý thuyết 1.5×.

Quan sát then chốt khi gộp: Pass 3 tính $e^{x_i - m} / d$ cần $d$ (tổng mũ), mà $d$ chỉ có sau Pass 2. Nếu **không lưu kết quả trung gian của Pass 2**, chỉ giữ $m$ và $d$, rồi ở lần hai vừa tính $e^{x_i - m}$ vừa chia cho $d$, ta được sự hợp nhất.

Thực ra, **phương án hai lần thuần** cần thuật toán **Online Softmax** (chủ đề bài sau). Ở đây ta chọn cách trung gian — hợp nhất một phần Pass 2 và Pass 3: ở lần 2, mỗi thread tạm ghi $e^{x_i - m}$ của mình vào Shared Memory, sau khi có $d$ toàn cục thì đọc ngay từ SMEM và ghi kết quả chuẩn hóa, tránh lần đọc global thứ ba.

### 6.2 Kernel

```cuda
// V4: kernel hai lần (Pass 1 tìm max, Pass 2 hợp nhất exp-sum + normalize)
// Cần thêm Shared Memory để tạm lưu giá trị exp
__global__ void softmax_v4(float* input, float* output, int M, int N) {
    extern __shared__ float smem[];  // size = N (tạm lưu giá trị exp)

    int row = blockIdx.x;
    int tid = threadIdx.x;

    float* x = input  + row * N;
    float* y = output + row * N;

    float4* x4 = reinterpret_cast<float4*>(x);
    int N4 = N / 4;

    // Pass 1: tìm max hàng (vector hóa + Warp Shuffle)
    float local_max = -INFINITY;
    for (int i = tid; i < N4; i += blockDim.x) {
        float4 data = x4[i];
        local_max = fmaxf(local_max, fmaxf(fmaxf(data.x, data.y),
                                            fmaxf(data.z, data.w)));
    }
    for (int i = N4 * 4 + tid; i < N; i += blockDim.x) {
        local_max = fmaxf(local_max, x[i]);
    }
    float max_val = blockReduceMaxShuffle(local_max);

    // Pass 2: tính exp và tạm lưu, đồng thời cộng sum
    float local_sum = 0.0f;
    for (int i = tid; i < N; i += blockDim.x) {
        float exp_val = expf(x[i] - max_val);
        smem[i] = exp_val;  // tạm lưu vào Shared Memory
        local_sum += exp_val;
    }
    float sum = blockReduceSumShuffle(local_sum);

    // Đọc exp từ Shared Memory và ghi kết quả chuẩn hóa
    float inv_sum = 1.0f / sum;
    for (int i = tid; i < N; i += blockDim.x) {
        y[i] = smem[i] * inv_sum;
    }
}
```

### 6.3 Hạn chế và khi nào dùng

⚠️ **Lưu ý**: V4 cần $N \times 4$ byte Shared Memory để tạm lưu exp. Khi $N=4096$ cần 16KB, trên A100 (164KB Shared Memory mỗi SM) hoàn toàn đủ. Nhưng khi $N$ lớn (ví dụ từ 32768 trở lên), Shared Memory không chứa nổi cả hàng — phương án này không còn phù hợp.

Với $N$ lớn, giải pháp thật sự là **Online Softmax** — chỉ cần một lần quét (hoặc hai, nhưng không cần tạm lưu cả hàng). Bài sau sẽ nói chi tiết.

| Tình huống | Phương án nên dùng |
|------------|--------------------|
| $N \leq 4096$ (SMEM chứa được) | V4 hợp nhất hai lần |
| $N > 4096$ (SMEM không đủ) | V3 ba lần quét, hoặc Online Softmax |

**V4 đo thực tế: ~75% băng thông (~1529 GB/s)** (với $N=4096$), khoảng 1.15× V3.

## 7. So sánh hiệu năng và gợi ý thực tế

### 7.1 Tổng hợp các phiên bản

| Phiên bản | Điểm tối ưu chính | Tỷ lệ băng thông | Tăng tốc tương đối |
|-----------|-------------------|------------------|--------------------|
| V0 1 thread/hàng | Không | ~5% | 1.0x |
| V1 Block song song | Nhiều thread hợp tác + coalesced + SMEM reduce | ~35% | 7.0x |
| V2 Warp Shuffle | Reduce hai tầng ở mức register | ~52% | 10.4x |
| V3 Tải vector hóa | float4 giảm số lệnh | ~65% | 13.0x |
| V4 Hợp nhất hai lần | Giảm một lần đọc global | ~75% | 15.0x |

📌 **Điểm then chốt**: Với $N=4096$, V4 đạt ~75% băng thông. Muốn đi tiếp cần Online Softmax — giảm số lần quét từ phía thuật toán.


### 7.2 Lựa chọn trong thực tế

| Tình huống | Phương án nên dùng |
|------------|--------------------|
| Học / giảng dạy | V1 hoặc V2 — logic rõ |
| Production với $N \leq 4096$ | V4 (hợp nhất hai lần + Warp Shuffle + float4) |
| Production với $N > 4096$ | Online Softmax (bài sau) |
| Đuổi hiệu năng tối đa | Dùng cuDNN hoặc bản hợp nhất trong FlashAttention |

💡 **Gợi ý**: Trong các framework suy luận LLM thực tế (vLLM, TensorRT-LLM, …), Softmax thường được hợp nhất với phần còn lại của Attention (Scale, Mask, MatMul) thành một Kernel lớn, tránh ghi kết quả trung gian xuống global memory. Tối ưu Softmax đứng riêng chủ yếu để hiểu nguyên lý và cho vài tình huống độc lập (ví dụ Softmax ở lớp phân loại).

## 📝 Tóm tắt

Từ V0 đến V4, tối ưu Softmax đi theo ba trục:

1. **Tăng độ song song**: từ một thread xử lý cả hàng → nhiều thread trong Block hợp tác, dùng reduce để tính max và sum song song (V0 → V1)
2. **Tăng tốc reduce**: từ vòng lặp Shared Memory naive → reduce hai tầng Warp Shuffle, trao đổi dữ liệu ở mức register, giảm mạnh sync và latency truy cập (V1 → V2)
3. **Giảm truy cập bộ nhớ**: từ tải từng phần tử → vector hóa float4 → hợp nhất hai lần để bớt đọc lặp, tiến gần trần lý thuyết của memory-bound (V2 → V3 → V4)

Bước nhảy tiếp theo — **từ ba lần quét xuống một lần** — cần thiết kế lại ở mức thuật toán. Đó là việc Online Softmax ở bài sau giải quyết.

## 🎯 Danh sách tự kiểm

- Giải thích vì sao Softmax naive bị tràn số trên FP32/FP16
- Chứng minh việc "trừ max" không đổi kết quả Softmax
- Nói rõ từng lần quét của Safe Softmax làm gì và vì sao cần ba lần
- Viết được CUDA reduce song song cấp Block cho max và sum
- Dùng `__shfl_down_sync` để làm max-reduce và sum-reduce trong Warp
- Giải thích đủ quy trình reduce hai tầng (trong Warp + giữa các Warp)
- Nói được yêu cầu căn chỉnh và nguồn lợi hiệu năng của tải float4
- Phân tích giới hạn dung lượng Shared Memory của phương án hợp nhất hai lần
- Chọn Softmax phù hợp theo độ lớn của $N$
- Dùng Nsight Compute đo tỷ lệ băng thông Softmax Kernel và tìm điểm nghẽn
